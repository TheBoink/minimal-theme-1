PICO POST — PICO 2 W SETUP

Connect the external normally-open button between physical pin 19 (GP14) and
physical pin 18 (GND), with the Pico powered off. The LCD's A button is no
longer used as the input; the app labels external-button events as button A.

First install or migration from the old main.py:
1. In Thonny, open your existing Pico main.py and privately note WIFI_SSID,
   WIFI_PASSWORD, MESSAGE_URL and PAIRING_KEY. Do not post or save those values
   in the Anvil asset templates. Use your existing pairing key to retain history.
2. Open the supplied pico_config.py template and put those four values in your
   PRIVATE copy. Save it to the Pico as pico_config.py, next to main.py and
   lcd_driver.py. The template also contains optional timing settings.
3. Save the updated main.py to the Pico. Keep your existing lcd_driver.py and
   installed requests and ntptime packages. Restart the Pico. Later firmware
   updates only need a new main.py; keep your private pico_config.py.

For a new Pico, install MicroPython for Pico 2 W, select it in Thonny, install
requests and ntptime on the Pico, and save Waveshare's Pico-LCD-1.3 MicroPython
sample as lcd_driver.py. In the published app, create a display and copy its
private pairing key and complete Device polling endpoint into pico_config.py.

After restarting, the LCD should show the Amsterdam clock and the previous
three days' activity. Press the external button and check that the app's count
and chart update. Both the Pico and app must use the same pairing key.

The private config file is stored on the Pico as readable text: treat the Pico
and any local copies as containing your Wi-Fi password and pairing key. Never
put real credentials in the app's downloadable template or share them in chat.

Troubleshooting:
- No module named pico_config: save pico_config.py to the Pico, next to main.py.
- ImportError for a config name: copy the complete template and add your values.
- Configuration error: check the four values, especially the full HTTPS URL.
- No module named requests, ntptime or lcd_driver: install/save it on the Pico.
- Pairing key rejected: use the same existing key in the Pico config and app.
- HTTP 404: copy the complete polling endpoint from the published app.

POLL_SECONDS defaults to 3. WATCHDOG_TIMEOUT_MS defaults to 8000 and must be
1000–8000; HTTP_TIMEOUT_SECONDS defaults to 3 and must be positive and shorter
than the watchdog. Slow DNS/TLS/network operations can still exceed the watchdog.
The Pico waits five seconds before starting the watchdog, allowing Ctrl+C in
Thonny for maintenance. A watchdog reset discards button presses still queued
only in RAM; saved database rows remain available.

Each two-hour activity box covers Amsterdam local time. Zero presses are light
green, 1–9 yellow, 10–19 orange, and 20+ red. Rows run oldest to newest.
Records use server receipt time, so presses queued offline are grouped when
received. The clock syncs over Wi-Fi; the last received timezone offset is used
when offline. The browser's 10-minute chart and diagnostic timestamps use UTC.

EXTERNAL BUTTON DEBOUNCE
The GP14 input is sampled with a soft timer, nominally every 10 ms. It must
remain pressed for at least 100 ms before counting, and then remain released
for at least 100 ms before another press can count. Timer callbacks may be
delayed during network requests, so short presses can be missed. A noisy signal
that stays low for 100 ms can still look like a press.
Install the new main.py on the Pico and keep your existing pico_config.py.

DOUBLE GP22 PULSE
For each accepted external button press (GP14, physical pin 19), GP22
(physical pin 29) pulls low for 100 ms, releases for 500 ms, pulls low for
another 100 ms, and then returns to high impedance.
The output is released at startup. Holding the input button does not repeat the
pulse; release and press again. Button history is still reported to the app.
These are nominal timings. A stalled Pico can hold it low until its
watchdog resets; reset/power loss releases the open-drain output.

Do not connect GP22 directly to the 3.7 V battery device: a charged cell can
reach 4.2 V, beyond the Pico's 3.3 V GPIO range. Use a properly rated isolated
interface, such as a relay module with low-current dry contacts, a 3.3 V
compatible active-low control input, and appropriate power/driver circuitry.
Confirm the target device's switch contact arrangement and ratings before
wiring. Do not connect a relay coil directly to GP22. Test the output and the
interface separately before connecting the target device.
Install updated main.py; your existing pico_config.py does not need changes.

STARTUP LOGO
After the five-second maintenance delay and display initialization, the LCD
shows the PICO POST logo for 10 seconds, then connects and shows the normal
screen. The watchdog is fed during the logo. The external button remains active
during the logo and can trigger its GP22 pulse. Install the new main.py and
keep the existing private pico_config.py.

CUSTOM STARTUP IMAGE
1. Save your square DrinkBuddy image on your computer, e.g. drinkbuddy.png.
2. Copy convert_logo.py to your computer. Install Pillow if needed:
      python -m pip install Pillow
3. Run:
      python convert_logo.py drinkbuddy.png startup_logo.rgb565
4. In Thonny, upload startup_logo.rgb565 to the Pico root, next to main.py.
   Also install the updated main.py; retain your existing pico_config.py.
5. Restart. The image appears for 10 seconds after the maintenance delay.

The converter produces 115,200 bytes, 240x240 RGB565 with high byte first.
The Pico reads it directly into the LCD framebuffer in small chunks. With no
image file the built-in PICO POST wordmark is shown. An image with the wrong
file size raises an error instead of displaying incomplete data.
The external button remains active while the startup screen is showing.

LOGO SCREENSAVER
After 30 seconds without an accepted external button press, the LCD displays
startup_logo.rgb565, or the built-in wordmark if no image is installed. The
next accepted press wakes the display and also performs the normal button action,
including both GP22 pulses and recording the event. The normal screen is drawn
again; polling, Wi-Fi retries and the watchdog continue while the logo is shown.
The 30-second period begins after the startup logo. Soft timer callbacks and
blocking network operations may delay activation or wake-up; presses shorter than
the debounce period may be missed. Install updated main.py and keep pico_config.py
and startup_logo.rgb565 on the Pico.

PICO POST — MICRO­PYTHON SETUP

Target: Raspberry Pi Pico 2 W with Waveshare Pico-LCD-1.3 (240 x 240).
The plug-on board has a joystick and A/B/X/Y buttons. A separate wired module
may use other pins. The official driver uses GPIO 10 SCK, 11 MOSI, 9 CS,
8 DC, 12 RESET, and 13 backlight. GPIO numbers are not physical pin numbers.

1. Install stable MicroPython for Pico 2 W:
   https://micropython.org/download/RPI_PICO2_W/
   Hold BOOTSEL while connecting USB; copy the downloaded UF2 to the drive.

2. Open Thonny and choose the MicroPython (Raspberry Pi Pico) interpreter.
   Use a 2.4 GHz Wi-Fi network.

3. Download Waveshare's official MicroPython demo:
   https://raw.githubusercontent.com/waveshare/Pico_code/main/Python/Pico-LCD-1.3/Pico-LCD-1.3.py
   Save it on the Pico as lcd_driver.py. Importing it does not run its demo.

4. Install the MicroPython requests package through Thonny's package manager,
   targeting the Pico (not the computer). If it is already importable, skip this.
   Alternatively, after connecting the Pico to Wi-Fi, run in its shell:
       import mip
       mip.install('requests')

5. Open the published Pico Post app. Click Create a new display and keep its
   pairing key. Copy the complete Device polling endpoint shown in that app.
   Use the published app endpoint for everyday use, not an expiring agent URL.

6. Copy the supplied main.py to your computer. Edit its four placeholders there:
   WIFI_SSID, WIFI_PASSWORD, MESSAGE_URL, PAIRING_KEY.
   Store your actual credentials only on your own computer/Pico, not in the
   Anvil Assets copy of the template. Save the configured file to the Pico as
   main.py, next to lcd_driver.py. Existing main.py files should be backed up.

7. Run main.py in Thonny. After saving, it also starts automatically on reboot.
   In the app, enter a message, click Send, wait a few seconds, then click
   Check connection & delivery. Expect Pico online and Display confirmed.

The receiver preserves the last message during network failures and retries.
Authentication and unexpected HTTP/programming errors stop with a traceback in
Thonny rather than pretending that delivery succeeded. Long messages wrap;
messages with many newlines cycle through pages. Acknowledgement follows the
last page. A newer message replaces an older one, even during pagination.

Troubleshooting:
- No module named requests: install the package on the Pico.
- No module named lcd_driver: check that filename and save location.
- Pairing key rejected: use the same saved key in the app and Pico.
- HTTP 404: copy the entire endpoint shown in the published app.
- Blank LCD: verify the model, orientation, headers and driver/pins first.

Physical LCD/Wi-Fi operation still requires testing on your actual hardware.

BUTTON A UPDATE
Replace main.py on your Pico with the updated template, restoring your four
local configuration values. Keep lcd_driver.py. Restart the Pico.
Press A (GPIO 15, active low). With the same pairing key entered in the app,
"From your Pico" updates automatically, usually within a few seconds.
Holding A counts once; presses less than 200 ms apart are debounced.
Presses during network failures are retained in RAM and retried; restarting
or powering off the Pico discards any unsent presses. Do not run two Pico
receivers with the same pairing key. The latest received event remains visible
after reopening the app and entering that key.

PICO POST — PICO 2 W SETUP

Connect the external normally-open button between physical pin 19 (GP14) and
physical pin 18 (GND), with the Pico powered off. The LCD's A button is no
longer used as the input; the app labels external-button events as button A.

First install or migration from the old main.py:
1. In Thonny, open your existing Pico main.py and privately note WIFI_SSID,
   WIFI_PASSWORD, MESSAGE_URL and PAIRING_KEY. Do not post or save those values
   in the Anvil asset templates. Use your existing pairing key to retain history.
2. Open the supplied pico_config.py template and put those four values in your
   PRIVATE copy. Save it to the Pico as pico_config.py, next to main.py and
   lcd_driver.py. The template also contains optional timing settings.
3. Save the updated main.py to the Pico. Keep your existing lcd_driver.py and
   installed requests and ntptime packages. Restart the Pico. Later firmware
   updates only need a new main.py; keep your private pico_config.py.

For a new Pico, install MicroPython for Pico 2 W, select it in Thonny, install
requests and ntptime on the Pico, and save Waveshare's Pico-LCD-1.3 MicroPython
sample as lcd_driver.py. In the published app, create a display and copy its
private pairing key and complete Device polling endpoint into pico_config.py.

After restarting, the LCD should show the Amsterdam clock and the previous
three days' activity. Press the external button and check that the app's count
and chart update. Both the Pico and app must use the same pairing key.

The private config file is stored on the Pico as readable text: treat the Pico
and any local copies as containing your Wi-Fi password and pairing key. Never
put real credentials in the app's downloadable template or share them in chat.

Troubleshooting:
- No module named pico_config: save pico_config.py to the Pico, next to main.py.
- ImportError for a config name: copy the complete template and add your values.
- Configuration error: check the four values, especially the full HTTPS URL.
- No module named requests, ntptime or lcd_driver: install/save it on the Pico.
- Pairing key rejected: use the same existing key in the Pico config and app.
- HTTP 404: copy the complete polling endpoint from the published app.

POLL_SECONDS defaults to 3. WATCHDOG_TIMEOUT_MS defaults to 8000 and must be
1000–8000; HTTP_TIMEOUT_SECONDS defaults to 3 and must be positive and shorter
than the watchdog. Slow DNS/TLS/network operations can still exceed the watchdog.
The Pico waits five seconds before starting the watchdog, allowing Ctrl+C in
Thonny for maintenance. A watchdog reset discards button presses still queued
only in RAM; saved database rows remain available.

Each two-hour activity box covers Amsterdam local time. Zero presses are light
green, 1–9 yellow, 10–19 orange, and 20+ red. Rows run oldest to newest.
Records use server receipt time, so presses queued offline are grouped when
received. The clock syncs over Wi-Fi; the last received timezone offset is used
when offline. The browser's 10-minute chart and diagnostic timestamps use UTC.

EXTERNAL BUTTON DEBOUNCE
The GP14 input is sampled every 10 ms. It must remain pressed for ten samples
before one event is counted, then remain released for ten samples before the
next press can be counted. This suppresses brief bounce on both edges and works
while the Pico is handling network requests. Extremely short presses may not be
counted; a noisy signal that stays low for 100 ms can still look like a press.
Install the new main.py on the Pico and keep your existing pico_config.py.
